## Ordered steps (clean machine → debug APK)

```bash
# 1. Node
nvm install 20 && nvm use 20   # or: nvm use

# 2. Install JS deps
npm install --no-audit --no-fund

# 3. Web build + checks
npm run build
npm run lint
npm run test:bg

# 4. Add Android platform (ONLY if android/ does not exist)
#    If android/ already exists from a previous run, skip this step.
npx cap add android

# 5. Apply AXON overlay (custom service, plugin, manifest permissions, icon)
#    Safe to run twice.
chmod +x scripts/apply-android-overlay.sh
./scripts/apply-android-overlay.sh

# 6. Sync web assets into the native project
npx cap sync android

# 7. Assemble debug APK (requires JDK 21 + Android SDK)
cd android
./gradlew assembleDebug
# APK path:
#   android/app/build/outputs/apk/debug/app-debug.apk
```

Or from repo root after overlay + sync:

```bash
npm run android:assemble
```

## Permissions required at runtime

- `POST_NOTIFICATIONS` (Android 13+)
- Foreground service (`FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`) — both required; FOREGROUND_SERVICE is not skipped
- `WAKE_LOCK` (PARTIAL_WAKE_LOCK while job active)
- Battery optimization exemption (user action via Settings deep link)

## Foreground service type

**`specialUse`** — Android 15+ caps `dataSync` and `mediaProcessing` at 6 hours per 24 hours.  
Source: https://developer.android.com/develop/background-work/services/fg-service-types  
`onTimeout(int)` and `onTimeout(int, int)`: checkpoint, log `TIMEOUT`, release wake lock, `stopSelf()`.

## Notes

- Idle = no service, no wake lock, no timer.
- Heartbeats every 5s on a **background ScheduledExecutorService** (not main Handler).
- PARTIAL_WAKE_LOCK tag `axon:bgproof` only while a job is active; WAKELOCK_ACQUIRED / WAKELOCK_RELEASED logged on every path.
- Log is append-only JSON Lines; SUMMARY every ~10 min then prune detailed HEARTBEAT lines.
- Web/browser builds: *cannot run in background; foreground only*.
- `npx cap add android` refuses when `android/` already exists — delete or use overlay only.

## File saving and export rule

All saving and exporting must go through `saveFile()` (`src/services/saveFile.ts`) and never use `<a download>` or `URL.createObjectURL` directly in screens or components. Inside the Capacitor Android WebView, standard `<a download>` clicks silently do nothing; `saveFile()` transparently routes through `@capacitor/filesystem` (writing to cache) and `@capacitor/share` (opening the native system share sheet) on native Android, while preserving standard browser downloads on the web (AI Studio preview).
